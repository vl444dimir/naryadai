# НарядAI — интерфейс

React + TypeScript для существующего FastAPI backend. Рабочий сразу видит свои задания и ближайшее действие; основные кнопки крупные, формы разбиты по задаче, фотографии добавляются кнопкой «Фото» из камеры или галереи. Управление встряхиванием отсутствует.

| Роль | Что доступно |
| --- | --- |
| Рабочий | Принятие/очередь/отказ, начало/пауза/продолжение, результат с материалами и фото, свои отчёты, уведомления. |
| Мастер | Выдача и изменение нарядов, доска статусов, приёмка/доработка, рассмотрение отказов и повторов, простои, сотрудники на смене, отчёты. |
| Руководитель | Просмотр нарядов, смен, рейтингов, материалов, простоев и проблем, Excel, настроенные модельные пояснения. |
| Администратор | Возможности мастера, справочники и учётные записи, роли, пароль/ПИН, смены. |

Подробная сверка API и известных ограничений — [COVERAGE.md](COVERAGE.md). Наличие кнопки не считается подтверждением работы на настоящем телефоне.

## Запуск

Нужен Node.js 24. Backend требует Python 3.12+ и PostgreSQL 16; его подготовка описана в [корневом README](../README.md). На подготовленной машине общий запуск предусмотрен скриптом [Start-NaryadAI.ps1](../scripts/Start-NaryadAI.ps1).

Для запуска только интерфейса откройте PowerShell **в корне проекта**. Права администратора и перезагрузка не нужны:

```powershell
Set-Location frontend
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). API должен уже работать на `http://127.0.0.1:8000`; Vite направляет туда `/api` и `/health`. Для проверок результатов и сроков нужен отдельный backend worker. Завершение Vite — Ctrl+C в его терминале.

Порт закреплён: если 5173 занят, Vite завершится с ошибкой, не выберет другой адрес. Сервер слушает только этот компьютер; данная команда не открывает приложение телефонам в локальной сети.

## Настройки и демонстрация

Значения по умолчанию позволяют работать без `frontend/.env`. Для своей конфигурации выполните из папки `frontend`:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

| Переменная | Значение примера | Назначение |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `/api` | Адрес API; рекомендуемый режим — тот же origin с прокси. |
| `VITE_SHOW_DEMO` | `true` | Показать кнопки заполнения демонстрационного входа. `false` скрывает их. |
| `VITE_DEMO_PASSWORD` | `Demo-Only-2026!` | Пароль синтетических аккаунтов, который кнопки подставляют в форму. Должен совпадать с подготовленным backend. |

**Все `VITE_*` доступны посетителю в JavaScript.** Здесь нельзя хранить API-ключи, токен Telegram, пароль базы или пароль реального сотрудника. Для стенда с реальными пользователями отключите демо-кнопки и удалите демо-пароль из конфигурации. Это не заменяет управление аккаунтами на сервере. Изменения `.env` требуют перезапуска dev-сервера, для production — новой сборки.

Кнопки ролей заполняют форму; вход выполняется отдельным нажатием. Seed backend создаёт `demo.worker01`, `demo.master1`, `demo.leader`, `demo.admin` и другие тестовые аккаунты. ПИН нужно отдельно назначить администратором; общего ПИН нет.

## Сборка и PWA

В PowerShell из папки `frontend`:

```powershell
npm run build
npm run preview
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173). Preview использует тот же прокси к API на 8000. Это проверочный локальный сервер; он также слушает только этот компьютер.

Сборка лежит в `dist`. Она содержит manifest, иконки и service worker с перечнем публичных ресурсов конкретной сборки. Service worker регистрируется **только в production**, поэтому `npm run dev` не проверяет его поведение.

Для размещения готового `dist` сервер должен отдавать приложение от корня `/`, возвращать `index.html` для маршрутов приложения и направлять `/api` к backend на том же origin. Должны быть доступны `/manifest.webmanifest`, `/sw.js` и `/assets/*`. Один архив `dist` не включает FastAPI, базу и worker. Размещение в подпапке текущей конфигурацией не предусмотрено.

## Потеря связи и черновики

Черновики привязаны к пользователю. При сетевом сбое интерфейс сохраняет ввод и показывает, что результат отправки не подтверждён. Явный повтор неопределённой операции использует прежний `operation_id`, чтобы не создать второй наряд или результат. Конфликт версии требует обновления карточки; текст и выбранное фото сохраняются. После известного конфликта отправляется новая операция с актуальной версией.

После истечения сеанса черновики остаются для повторного входа. Явный выход очищает черновики этого пользователя из localStorage и sessionStorage. Секреты учётных записей в черновики не записываются.

PWA кэширует публичную оболочку, **не API и персональные фото**. Полной офлайн-синхронизации нет: автоматической отправки накопленных действий не выполняется, для работы с актуальными нарядами нужен backend.

## Проверка

Из папки `frontend`:

```powershell
npm test
npm run check:reports
npm run build
```

Тесты проверяют DOM, правила интерфейса, обработку запросов и отчёты. Они не заменяют проверку камер, адаптивного вида и действий в браузере телефона. Итоги конкретного прогона фиксируются отдельно основным процессом разработки.

Модель и Telegram показываются как отключённые, если backend не настроен; интерфейс не обещает модельную проверку или доставку уведомлений в таком состоянии. Числа отчётов и правила рассчитывает backend, модель может отдельно пояснять их.

Реальная браузерная и телефонная проверка, установка PWA, камера/галерея, работа в перчатках и сроки доставки пока не подтверждены. Ограничение передачи чужих персональных оценок сервером при бригадном доступе зафиксировано в [COVERAGE.md](COVERAGE.md): скрытие полей интерфейсом не исправляет серверный ответ. Этот frontend не изменяет backend.
