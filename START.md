# НарядAI Старт разработки и первые четыре часа

Первый результат — один наряд проходит полный путь между двумя настоящими телефонами и сохраняется на сервере: мастер выдаёт, исполнитель принимает и начинает, прикладывает результат с фото, мастер принимает работу. Это общий рубеж для команды из трёх человек.

Стек команды подтверждён: React + TypeScript, Python + FastAPI. Для общей базы — PostgreSQL. Один адаптивный PWA-клиент для мастера и исполнителя, один сервер приложения.

## Первые тридцать минут

1. Распределить три направления из таблицы ниже и назначить ответственного за объединение изменений.
2. Зафиксировать общие поля и статусы наряда. FastAPI публикует контракт API, интерфейс и ИИ используют его названия.
3. Выбрать два телефона для проверки: мастер и исполнитель. Сразу подготовить доступ к приложению по HTTPS.
4. Выбрать один канал фоновых уведомлений и проверить тестовую доставку на телефоне. Кейс допускает Telegram-бот или аналог; если команда уже умеет FCM, использовать знакомый канал.
5. Создать минимальные тестовые данные: один участок, один насос, один мастер, два исполнителя, несколько шифров и материалов. Полный набор из кейса готовится параллельно.

## Распределение команды

| Участник | Первые четыре часа | Следующий этап |
| --- | --- | --- |
| 1 Интерфейс | Вход, экран смены, выдача, карточка исполнителя, камера, форма результата, приёмка мастером | Все действия по статусам, короткая выдача |
| 2 Сервер | Роли, база, API нарядов и фото, переходы, журнал, обновление экранов, тестовое уведомление | Сроки, эскалации, переназначение, защита от повторных действий |
| 3 ИИ и данные | Тестовые справочники, генератор истории, набор хороших и плохих результатов, контракт проверки; прогон на устройствах вместе с командой | Настоящая ИИ-проверка, фото, отчёты, рейтинг, память оборудования |

ИИ-помощникам выдавать задачи внутри своего направления. Общие модели и контракт меняются согласованно; независимые помощники не переименовывают поля и состояния самостоятельно.

## Контракт который нужен до параллельной разработки

Наряд: ID, номер, тип, описание, участок, оборудование, исполнитель, мастер, приоритет, срок, норматив, статус, версия и времена событий. Номер, мастер и дата выдачи заполняются сервером.

Результат: выполненные работы, шифр, материалы с количеством и единицей, явное отсутствие использованных материалов при необходимости, фото после, комментарий и версия результата.

Событие: наряд, автор, действие, серверное время, прежнее и новое состояние, причина. Проверка ИИ и окончательное решение мастера хранятся отдельно.

Статусы из схемы кейса: выдан, принят, в очереди, отклонён, в работе, приостановлен, исполнено, проверка ИИ, на доработку, закрыт. Отмена мастером фиксируется отдельно. Просрочка — признак поверх статуса, поэтому «в работе» не исчезает при наступлении срока.

Для первого прогона используются переходы «выдан → принят → в работе → исполнено → закрыт». До подключения модели интерфейс явно показывает ручную приёмку. Все остальные обязательные действия добавляются в следующем этапе; первый прогон не является готовым MVP.

Сервер определяет роль по сессии, проверяет допустимость перехода и сохраняет изменение вместе с событием. Повтор действия имеет один идентификатор: два нажатия не должны создавать два списания. После переподключения клиент загружает актуальное состояние.

## Рубежи первых четырёх часов

| Время от начала | Что проверяем |
| --- | --- |
| До 1 часа | Приложение открывается на телефонах, роли входят; проверен выбранный канал фонового уведомления |
| До 2 часов | Мастер создаёт наряд; исполнитель видит его; данные сохраняются после обновления страницы |
| До 3 часов | Принятие и начало отражаются у мастера; исполнитель прикладывает фото, работы и материалы |
| До 4 часов | Мастер принимает результат; журнал показывает участников и времена; цикл повторяется на втором задании |

Не переходить к расширению интерфейса, пока созданный на одном телефоне наряд не появился на другом через настоящий сервер. Отдельные красивые экраны не подтверждают прохождение этого рубежа.

## Добавление фото

Большая кнопка «Фото» открывает камеру с первого прогона. Снимок прикрепляется к черновику текущего результата; отправка результата выполняется отдельным действием.

## Что делать после первого рубежа

1. Добавить очередь, отказ и паузу с причинами, доработку, отмену, переназначение и все обязательные поля.
2. Подключить сроки и настоящую ИИ-проверку с оценкой, замечаниями и источниками; мастер принимает окончательное решение.
3. Собрать сменный отчёт и рейтинг; загрузить 500+ нарядов за три месяца и минимальные справочники из кейса.
4. Добавить память оборудования и объяснимое сравнение фото. Затем QR при резерве времени.
5. Зафиксировать время для прогона всех шагов демо, измерения выдачи и обновления, презентации и резервного видео.

Полная концепция, обязательный объём, ограничения ИИ и план на 24 часа находятся в [основном исследовании](research/RESEARCH.md).
